# 元数据规范

> Bases 仪表盘全靠这些字段工作。字段写错，视图就是空的。

## 通用字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | 文本 | `book` / `permanent` / `article` / `ai-dialogue` / `person` / `moc` / `fleeting` |
| `title` | 文本 | 与文件名一致 |
| `topics` | **列表 + 双链** | `- "[[课题分离]]"`，用于跨书串联 |
| `tags` | 列表 | 见下方标签体系 |
| `created` | 日期 | `YYYY-MM-DD` |
| `last_reviewed` | 日期 | 驱动「待回顾」视图 |

## 图书笔记（`type: book`）

```yaml
---
type: book
title: 被讨厌的勇气
title_en: The Courage to Be Disliked
author:                                    # 列表 + 双链
  - "[[岸见一郎]]"
  - "[[古贺史健]]"
translator: 渠海霞
publisher: 机械工业出版社
year: 2015
isbn13: "9787111495482"                    # 必须加引号
douban: https://book.douban.com/subject/26369699/
language: zh
pages: 232
cover: https://...jpg                      # 卡片视图封面
status: finished                           # inbox|reading|finished|abandoned
rating: 5                                  # 1-5
medium: paper                              # paper|eink|pdf
started: 2026-03-02
finished: 2026-04-18
last_reviewed: 2026-04-20
excerpt_pdf: "[[被讨厌的勇气-摘抄.pdf]]"     # 双链，不是纯文件名
topics:
  - "[[课题分离]]"
tags:
  - type/literature
  - type/book
created: 2026-03-02
---
```

### 三个容易踩的坑

1. **`isbn13` 必须加引号**。不加引号 YAML 会当成数字处理，丢掉信息。
2. **`author` 和 `topics` 必须是「列表 + 双链」**。这样 Bases 才能识别成 Link 对象，
   作者页里的 `list(author).contains(this)` 才能反查出这位作者的所有书。写成纯文本就失效了。
3. **`excerpt_pdf` 用双链**。这样图书笔记会成为 PDF 的反向链接，
   在 PDF++ 里读 PDF 时侧边栏能直接跳回来。

## 永久笔记（`type: permanent`）

```yaml
---
type: permanent
title: 一切烦恼都来自人际关系      # 标题必须是一个完整主张
status: budding                   # seedling(幼苗) | budding(成形) | evergreen(成熟)
confidence: 中                    # 高 | 中 | 低
topics:
  - "[[课题分离]]"
tags:
  - type/permanent
  - review                        # 打了才进间隔重复队列
created: 2026-04-19
last_reviewed: 2026-04-20
---
```

`status` 三级的判断标准：

- `seedling` 刚记下，还比较粗糙
- `budding` 想清楚了，有依据也有边界
- `evergreen` 反复验证过，被多则笔记引用，我愿意为它辩护

## 标签体系

标签只用来标**类型**，主题一律用 `topics` 双链。理由：标签是扁平的死数据，双链能双向导航、能进关系图谱。

```
type/book          图书笔记
type/literature    文献笔记（图书/文章/AI对话的父类）
type/article       网络资料
type/ai            AI 对话
type/permanent     永久笔记
type/person        人物
type/moc           地图
type/fleeting      闪念
type/journal       日记与复盘
type/meta          仓库文档

review             进入间隔重复队列
```

## Bases 常用写法速查

```yaml
# 筛选
- type == "book"
- 'status == "reading"'                  # 含双引号的语句整体用单引号包住
- file.hasTag("type/permanent")
- file.inFolder("20-Notes")
- '!excerpt_pdf.isEmpty()'
- list(author).contains(this)            # 「当前页面作为作者」的反查
- file.ctime >= today() - "30d"

# 公式
未回顾天数: 'if(last_reviewed, ((today() - last_reviewed) / 86400000).round(0))'
被引用: file.backlinks.length            # 注意：性能开销大，不自动刷新

# 日期运算单位：y M d w h m s
today() - "90d"
now() + "1 week"
```

两个注意点：

- 日期相减得到的是**毫秒**，换算成天要除以 `86400000`
- `file.backlinks` 官方标注**性能开销大且不会自动刷新**，别在大表里滥用

## 为什么用 Bases 而不是 Dataview

Dataview 最后一次实质更新是 **2025-04**，累积 662 个未处理 issue。
而 **Bases 是 Obsidian 官方核心插件**（2025 年下半年随版本内置），官方文档里的示例截图用的就是书单。

两者一个根本差别：

> Bases 默认扫描**全库**，没有 Dataview 那样的 `FROM`。收窄范围靠 `filters`。

本库所有仪表盘都是 Bases 原生的，不依赖任何社区插件。
