# 接入 AI 深度对话

> 结论先行：**用 Local REST API 插件内置的 MCP 服务器**接 Claude Code / Claude Desktop / Cursor。
> 网上教程推荐的那些第三方 Obsidian MCP server 现在都没必要了。

## 为什么是这个方案

Local REST API 插件（`obsidian-local-rest-api`，2890 星，2026-08 仍在活跃维护，仅 3 个未处理 issue）
从 v5 开始**内置了 MCP 服务器**。它的 README 直接写道：

> 「存在若干第三方 Obsidian MCP 服务器，但它们已经没有必要了 —— 本插件内置的 MCP 服务器运行在
> Obsidian 内部，可以直接访问库的实时元数据、当前打开的文件和命令面板。如果你正在用第三方服务器，
> 换成这个大概率效果更好。」

对比其他路子：

| 方案 | 状态 | 评价 |
| --- | --- | --- |
| **Local REST API 内置 MCP** | ✅ 活跃 | **首选**。能读实时元数据、能精确改写某个小节 |
| `obsidian-mcp-tools` | 🔴 **作者已归档** | 别用，README 明写项目终止 |
| `mcp-obsidian` 等第三方 | 🟡 还活着但多余 | 官方已表态没必要 |
| Smart Connections | ✅ 活跃 | **补充**用，不是替代。见下文 |
| Copilot 插件 | ✅ 活跃 | 想在 Obsidian 界面里跑 agent 才需要 |

## 配置步骤

### 1. 装插件并拿到 Key

1. 社区插件搜 `Local REST API` 安装启用
2. 插件设置里复制 **API Key**
3. 记下端口：HTTPS `27124` / HTTP `27123`

> ⚠️ 这个 Key 存在 `.obsidian/plugins/obsidian-local-rest-api/data.json`，
> 已经写进 `.gitignore`，**不要提交它**。

### 2. 接入 Claude Code

```bash
claude mcp add --transport http obsidian http://127.0.0.1:27123/mcp/ \
  --header "Authorization: Bearer 你的APIKEY"
```

### 3. 接入 Claude Desktop

编辑 `claude_desktop_config.json`：

```json
{
  "mcpServers": {
    "obsidian": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "http://127.0.0.1:27123/mcp/",
        "--header",
        "Authorization: Bearer 你的APIKEY"
      ]
    }
  }
}
```

配置细节以插件 README 为准（不同版本参数可能微调）。**Obsidian 必须开着**，MCP 服务器跑在它里面。

## AI 能做什么

内置的工具里，对读书笔记最有用的几个：

| 工具 | 用途 |
| --- | --- |
| `search_simple` / `search_query` | 全文搜索 / 按元数据结构化查询 |
| `vault_read` / `vault_list` | 读笔记、列目录 |
| `vault_patch` | **精确追加到某个小节或某个属性**，不用重写整篇 |
| `vault_get_document_map` | 拿到笔记的结构大纲 |
| `command_execute` | 调用 Obsidian 命令 |

`vault_patch` 特别关键 —— 它让 AI 可以把一条提炼结果**追加到图书笔记的 `## 提炼` 下面**，
而不是把你整篇笔记重写一遍。

## ⚠️ AI 读不了大 PDF

必须知道的限制：MCP 的 `vault_read_binary` **拒绝超过 1 MiB 的文件**（base64 编码后 token 消耗极高）。

**你那些几十 MB 的 GoodNotes PDF，AI 通过 MCP 是读不到的。**

这不是缺陷，反而印证了工作流的设计：

> **要让 AI 参与思考，知识必须先被你提炼成 Markdown。**
> PDF 是原始档案，永久笔记才是可对话的资产。

这也是为什么 [[02-工作流]] 里强调「一本书产出 3-5 则永久笔记」比堆一百条摘录更有价值 ——
提炼这一步同时服务于你自己的记忆和 AI 的可读性。

## 值得问的问题

配好之后，这类问题才是这个库的真正价值所在：

- 「翻一遍我 `20-Notes` 里所有标签含 `课题分离` 的笔记，找出彼此矛盾的地方」
- 「我读过的书里，哪些作者对『自由』的定义是互相冲突的？各自的论证前提是什么」
- 「看 `30-Maps/概念 MOC` 的悬而未决清单，挑一个和我深聊，先别给答案，先追问我」
- 「找出我 30 天没动过、但被引用超过 3 次的枢纽笔记，逐条问我现在是否还这么认为」
- 「读 `10-Sources/Books/XX.md` 的摘录部分，指出哪些我只是抄了原文却没有真正提炼」

最后一条尤其值得定期跑一次 —— 它治的是「假装读懂了」这个通病。

## 补充：Smart Connections

`smart-connections` 走的是另一条路：**本地向量检索，零配置，不需要 API Key，数据不出本机**。

它不是用来对话的，是用来**在你写笔记时自动提示「你以前写过相关的东西」**。
这正好补上 MCP 方案的短板 —— MCP 需要你主动提问，而 Smart Connections 是被动浮现。

注意它会生成 `.smart-env/` 索引目录，已经写进 `.gitignore`。

## 给 AI agent 的仓库说明

仓库根目录的 `AGENTS.md` 写好了本库的结构约定、命名规则和笔记纪律。
Claude Code、Codex 这类 agent 会自动读取它，从而知道该往哪写、按什么格式写。
换了工作流记得同步更新那个文件。
