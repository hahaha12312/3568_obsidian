# 三个月Linux内核学习计划
## 面向边缘AI系统架构方向

**目标**：三个月后，能基于内核机制对边缘AI系统的内存、调度、功耗、数据通路做出判断，并能在RK3568类平台上定位和优化相关问题。

**前提**：已有BSP和RK3568基础，学习以“理解 + 实践 + 记录”为主，不追求通读源码。

**建议投入**：每周 8–12 小时（可根据实际情况调整）。时间表仅为参考，不强制按周完成，以各阶段产出和检查点是否达成为准。

---

## 实验环境与基准负载

### 实验环境

| 项目 | 说明 |
|------|------|
| 平台 | RK3568（4×Cortex-A55 对称多核，NPU 约1TOPS，另有RGA、VPU、ISP、Mali GPU） |
| 内核 | 厂商 Linux 6.1（以板上 `uname -r` 和实际 config 为准） |
| 主要负载 | 视觉类模型推理（RKNN）；LLM/KV Cache 在该平台算力下不作为主线，仅作为延伸思考 |
| 注意 | RK3568 无大小核，EAS/capacity-aware 调度的收益有限，只做认知层面的对比学习 |

### 基准负载（第0周确定，三个月内保持不变）

- 固定一个模型（如一个常见检测或分类模型）、固定输入尺寸、固定输入源（图片循环或摄像头）、固定 batch。
- 固定三项指标：**平均延迟、P99延迟（抖动）、吞吐**，同时记录内存占用、CPU频率、温度。
- 所有实验都与第0周基线对比，保证各周数据可横向比较。

## 第0周：环境与基线

**目标**：确认实验环境，固定基准负载，建立后续所有实验的对比基线。

- **学习内容**：确认内核版本和关键 config（`/proc/config.gz` 或板上 config 文件）：CONFIG_PREEMPT 模型、CMA、THP、CGROUPS、SCHED_DEBUG、FTRACE、PERF_EVENTS 是否开启；了解 RK3568 的内存布局、设备树中 reserved-memory 与 NPU 节点
- **实践任务**：跑通基准负载，记录空载与推理时的延迟（平均、P99）、吞吐、内存、CPU频率、温度；编写可复用的采集脚本
- **产出**：环境清单、基准负载说明、基线数据表、采集脚本

---

## 第1个月：内存管理

**目标**：搞清楚模型权重、输入输出与中间特征图在系统中是怎么占用和流动的，能判断内存瓶颈。

### 第1周：物理内存、虚拟内存与模型文件加载
- **学习内容**
  - P0：物理内存分配基础（buddy、slab）、虚拟内存概念、**page cache 与模型文件加载**（文件读入、mmap 模型、冷启动与热启动）
  - P1：swap、zram、OOM killer 与 cgroup memory 的基本概念
- **实践任务**：用 `/proc/meminfo`、`free`、`top` 观察RK3568空载与加载模型后的内存变化；对比冷启动（清 page cache 后）与热启动的模型加载时间
- **产出**：内存占用对比记录、模型加载冷热对比

### 第2周：内存映射与保留内存
- **学习内容**
  - P0：用户态内存映射（mmap）、内核态内存分配接口、**CMA 与设备树 reserved-memory**
  - P0：这些机制分别从哪里划走了多少内存（`/proc/iomem`、`MemTotal` 与物理内存的差距）
- **实践任务**：写一个简单程序用mmap分配大块内存，观察与普通malloc的区别；查看板上 CMA 大小与使用情况，说明哪些设备占用了保留区
- **产出**：实验笔记、板级内存分布表

### 第3周：DMA、IOMMU与数据通路
- **学习内容**
  - P0：DMA与一致性内存、**ARM缓存一致性与cache维护**、**IOMMU**、DMA-BUF、dma-heap
  - P0：零拷贝数据通路的基本概念（buffer 如何在设备间传递而不拷贝）
- **实践任务**：了解RK3568 NPU数据如何从用户态传到NPU（看现有驱动或文档），确认驱动使用的是哪种缓冲区机制（DRM GEM、dma-heap 还是 CMA）
- **产出**：数据通路草图（用户态 → 内核 → NPU，标出每一步是否拷贝、是否有cache维护）

### 第4周：内存性能影响因素
- **学习内容**
  - P0：内存碎片、缓存行为对性能的影响
  - P1：大页（THP）、DDR带宽与DMC调频、swap/zram 对延迟的影响
- **实践任务**：在实际推理场景下观察内存碎片（`/proc/buddyinfo`）和带宽敏感情况（可用`perf`或简单计时）；在内存压力下运行基准负载，观察抖动变化
- **产出**：问题清单

**月末检查**（能回答以下问题）：
1. 为什么模型装得下，但推理还是慢或不稳定？
2. 加载一个模型后，`MemAvailable` 减少了多少？这部分内存在 page cache、匿名页、CMA 中分别占多少？
3. NPU 访问的 buffer 为什么常常必须是物理连续的或经过 IOMMU 映射？
4. 数据在 摄像头 → NPU 的路径上哪些地方发生了拷贝？
5. 内存压力（碎片、回收、swap）会通过哪些机制影响推理延迟？

## 第2个月：调度与实时性

**目标**：理解并控制任务优先级，减少推理延迟抖动。

### 第5周：CFS调度器与延迟测量基线
- **学习内容**
  - P0：CFS调度器基本原理、nice值、优先级；**cyclictest 的原理与使用**
- **实践任务**：先用 `cyclictest` 在空载和满载下建立系统延迟基线；再用`chrt`或`taskset`调整进程优先级，观察对推理延迟的影响
- **产出**：系统延迟基线、延迟对比数据

### 第6周：实时调度
- **学习内容**
  - P0：实时调度（SCHED_FIFO/RR）、CPU亲和性、RT 带宽限制（`sched_rt_runtime_us`）
  - P1：**优先级反转**、内核抢占模型（PREEMPT、PREEMPT_RT 的意义，对照板上实际 config）
- **实践任务**：把关键推理进程绑核并设为实时优先级，测试延迟抖动；构造一个简单的优先级反转场景并观察
- **产出**：实验记录

### 第7周：中断与多核
- **学习内容**
  - P0：中断亲和性、多核负载均衡
  - P1：**threaded IRQ、softirq**，中断对关键线程的影响
- **实践任务**：观察NPU中断和CPU任务的分布，尝试调整亲和性；观察中断密集时 `ksoftirqd` 的行为
- **产出**：中断与CPU分布图

### 第8周：关键路径保护
- **学习内容**
  - P0：**cgroup v2（cpu/cpuset）**、**isolcpus、nohz_full、rcu_nocbs** 等避免关键路径被抢占的方法
  - P2：uclamp、EAS/capacity-aware 调度（RK3568 为对称核，只做认知对比）
- **实践任务**：设计一个简单的“控制线程 + 推理线程”优先级与隔离方案并验证，用 cyclictest 和基准负载对比隔离前后
- **产出**：调度方案说明

**月末检查**（能回答以下问题）：
1. 能给出一套在RK3568上降低推理延迟抖动的调度策略，并有数据支持。
2. 实时优先级、绑核、核隔离三者分别解决什么问题，各有什么代价？
3. NPU 中断到达后，到推理线程被唤醒之间经过哪些内核环节，哪些环节会引入抖动？
4. 在 4×A55 对称核上，做核隔离会损失什么？
5. 什么情况下提高优先级反而会使系统整体变差？

## 第3个月：电源管理 + 热管理 + 调试 + 数据通路整合

**目标**：把前两个月的知识串起来，能做系统级分析和优化。

### 第9周：电源管理基础
- **学习内容**
  - P0：cpufreq、**devfreq（NPU/GPU/DMC）**、功耗状态
  - P1：**runtime PM**、休眠唤醒对推理服务的影响
- **实践任务**：调整CPU频率策略，再调整NPU/DMC频率，观察对推理性能和功耗的影响
- **产出**：功耗-性能曲线

### 第10周：热管理
- **学习内容**
  - P0：**thermal zone、cooling device、governor（如 step_wise）**、温度与降频机制、持续负载下的行为
- **实践任务**：做长时间推理测试，记录温度、频率、性能变化；找出降频触发点
- **产出**：热降频观察记录

### 第11周：调试与性能分析
- **学习内容**：ftrace、perf 深入使用，延迟分析思路（前面各周已逐步使用基础工具，本周系统化）
- **实践任务**：用perf或ftrace抓一次推理过程的关键路径（`perf sched`、`trace-cmd`）
- **产出**：性能分析报告

### 第12周：数据通路专题与综合实践
- **学习内容**
  - P0：**零拷贝数据通路专题**（V4L2 → DMA-BUF → RGA → NPU）；综合复习
- **实践任务**：
  - 前半周：梳理或实现一条图像采集到推理的零拷贝链路，对比有无拷贝的延迟与CPU占用
  - 后半周：选一个实际问题（如延迟抖动、内存不足或持续负载降频），用前面知识定位并优化
- **产出**：数据通路对比数据、完整问题分析文档

### 第13周：缓冲与复盘
- **内容**：补完前面未完成的实验或笔记；按“症状 → 子系统 → 工具 → 对策”整理问题库；回答三个月的全部检查点问题
- **产出**：复盘总结

**月末检查**（能回答以下问题）：

2. 看到“推理变慢”这一现象，能说出应依次检查哪些子系统、用什么工具、怎么区分是内存、调度、降频还是数据通路问题。

## 学习方法建议

- **以RK3568实际运行为主**：尽量在真实设备上观察，而不是只看理论。
- **问题驱动**：每周围绕一个具体问题学（例如“为什么加载模型后内存涨这么多”）。
- **先测量，后优化**：每个优化都要有基线数据对比，基准负载保持不变。
- **记录架构影响**：每次实验后写几句“这个内核机制对系统架构设计意味着什么”。
- **控制深度**：理解原理和关键路径即可，不必深入每个函数实现。
- **工具优先**：熟练使用 `/proc`、`perf`、`ftrace`、`top`、`chrt`、`cyclictest` 等工具，比纯读代码更实用。
- **版本意识**：以板上实际内核和 config 为准，教程与文档中的默认值可能与厂商内核不同。
